# ابزار بررسی هاست (Host Probe)

یک فایل PHP مستقل برای اندازه‌گیری **واقعی** قابلیت‌های هاست cPanel پیش از نصب. هیچ چیزی را نصب
یا تغییر نمی‌دهد (فقط یک پوشه موقت آزمایشی می‌سازد و پاک می‌کند).

## مراحل

1. در `probe.php` مقدار `PROBE_TOKEN` را به یک رشته تصادفی ≥ ۲۴ کاراکتر تغییر دهید.
   (بدون این تغییر، اسکریپت اجرا نمی‌شود.)
2. فایل را با File Manager در `public_html/` (یا docroot ساب‌دامین هدف) آپلود کنید.
3. باز کنید: `https://your-domain/probe.php?token=YOUR_TOKEN`
4. دکمه «اجرای تست‌ها» را بزنید (حدود ۴۰ ثانیه). در صورت تمایل اطلاعات یک دیتابیس خالی آزمایشی را برای تست وارد کنید.
5. اگر ارائه‌دهنده پیامک مشخص است، دامنه API آن را در «تست اتصال خروجی» بزنید.
6. «کپی گزارش» ← گزارش JSON را برای تیم توسعه بفرستید.
7. **«حذف فایل probe از سرور»** را بزنید یا فایل را دستی حذف کنید.

## چه چیزهایی بررسی می‌شود

| بخش | موارد |
|---|---|
| PHP | نسخه، SAPI، افزونه‌های الزامی/اختیاری، Argon2id، Ed25519 (sodium) |
| محدودیت‌ها | `upload_max_filesize`، `post_max_size`، `memory_limit`، `max_execution_time`، `disable_functions`، `open_basedir`، OPcache |
| فایل‌سیستم | docroot، امکان نوشتن خارج از docroot، فضای پارتیشن (با هشدار اینکه سهمیه حساب نیست) |
| پروسه | `exec`/`proc_open`، FFmpeg (فقط گزارش؛ برای E2EE استفاده نمی‌شود)، مسیر PHP CLI برای Cron |
| تست واقعی HTTP | حداکثر بدنه باینری و JSON قابل ارسال (ModSecurity / LimitRequestBody)، MIME فایل `.wasm`، اثر واقعی `.htaccess` در مسدودسازی پوشه، دوام درخواست ۲۵ ثانیه‌ای (امکان long-poll) |
| دیتابیس | نسخه، پشتیبانی `SKIP LOCKED`، InnoDB، `max_allowed_packet` |
| خروجی | اتصال HTTPS به دامنه دلخواه (پنل پیامک، سرویس push) |

## چیزهایی که از داخل PHP قابل تشخیص نیستند (باید از cPanel خوانده شوند)

- سهمیه دیسک و inode حساب (cPanel ← Disk Usage / Resource Usage)
- Entry Processes و محدودیت‌های CloudLinux LVE (cPanel ← Resource Usage)
- وجود و حداقل فاصله Cron Jobs (cPanel ← Cron Jobs)
- امکان تعیین docroot ساب‌دامین به پوشه دلخواه (cPanel ← Domains)

## تست انجام‌شده در فاز ۱

اسکریپت روی PHP 8.3 (built-in server) و MariaDB 10.11 در محیط توسعه اجرا شد: نگهبان توکن (۵۰۳ برای
توکن پیش‌فرض، ۴۰۴ برای توکن اشتباه، ۴۰۳ بدون HTTPS)، همه بررسی‌های ایستا، تست بدنه تا ۶۴MB، MIME wasm،
درخواست ۲۵ ثانیه‌ای و تست دیتابیس با موفقیت اجرا شدند. تست `.htaccess` در built-in server به‌درستی
«نشت» را تشخیص داد (این سرور `.htaccess` را پشتیبانی نمی‌کند) — یعنی تست عملاً کار می‌کند. **روی هاست
cPanel واقعی هنوز اجرا نشده است.**
