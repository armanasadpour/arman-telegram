# ۱۲ — راهنمای نصب روی cPanel (بدون SSH)

## پیش‌نیازها

- PHP 8.2 یا بالاتر با افزونه‌های `pdo_mysql`، `openssl`، `sodium`، `mbstring`، `curl`، `ctype` (در cPanel ← Select PHP Version)
- MySQL 8.0+ یا MariaDB 10.6+
- گواهی HTTPS فعال روی دامنه یا ساب‌دامین (cPanel ← SSL/TLS Status، AutoSSL)
- فایل `private-messenger-<نسخه>.zip` و فایل `.sha256` آن

## ۱. بررسی فایل

هش SHA-256 فایل ZIP را با مقدار فایل `.sha256` مقایسه کنید (در ویندوز: `certutil -hashfile file.zip SHA256`).

## ۲. ساخت دیتابیس

cPanel ← **MySQL® Database Wizard**: یک دیتابیس خالی و یک کاربر با رمز قوی بسازید و **ALL PRIVILEGES** بدهید.
نام کامل دیتابیس و کاربر (با پیشوند حساب، مثلاً `user_pm`) را یادداشت کنید.

## ۳. آپلود و استخراج

cPanel ← **File Manager** ← پوشه خانه (`/home/USER`، **نه** `public_html`) ← Upload ← فایل ZIP ← Extract.
نتیجه: `/home/USER/private-messenger/`.

سپس یکی از دو روش:

**روش A (پیشنهادی) — ساب‌دامین اختصاصی:** cPanel ← **Domains** ← Create A New Domain (مثلاً `x7.example.com`)
و Document Root را `private-messenger/public` بگذارید. نام ساب‌دامین را خنثی انتخاب کنید (مثلاً بدون کلمه chat/msg).

**روش B — دامنه اصلی:** دو فایل `private-messenger/public/index.php` و `private-messenger/public/.htaccess` را
به `public_html/` کپی کنید (برای دیدن `.htaccess` در File Manager گزینه Show Hidden Files را فعال کنید).
اگر `public_html` از قبل سایت دیگری دارد، از روش A استفاده کنید؛ این برنامه همه درخواست‌های آن دامنه را می‌گیرد.

## ۴. اجرای نصب‌کننده

1. در File Manager فایل `private-messenger/storage/install-token.txt` پس از اولین باز کردن صفحه نصب ساخته می‌شود.
2. مرورگر: `https://دامنه/install` ← صفحه درخواست کد نصب نمایش داده می‌شود.
3. فایل `install-token.txt` را در File Manager باز کنید، محتوا را کپی و در صفحه وارد کنید.
4. جدول «بررسی قابلیت‌های هاست» را بخوانید؛ موارد «مانع نصب» باید برطرف شوند.
5. اطلاعات دیتابیس و حساب مدیرکل (رمز ≥ ۱۰ کاراکتر) را وارد و «نصب» را بزنید.
6. **دو آدرس مخفی نمایش‌داده‌شده را فوراً در مدیر گذرواژه ذخیره کنید.** این آدرس‌ها دیگر نمایش داده نمی‌شوند
   (فقط در `config/.env` با نام‌های `APP_PATH` و `ADMIN_PATH` موجودند).

پس از نصب، `https://دامنه/`، `/install` و هر آدرس دیگر خطای 404 می‌دهد.

## ۵. Cron

cPanel ← **Cron Jobs** ← Common Settings: Every 15 minutes (یا کمترین فاصله مجاز) ← فرمان نمایش‌داده‌شده در صفحه
«سیستم» پنل مدیریت، مثلاً:

```
/usr/local/bin/php /home/USER/private-messenger/app/Cli/cron.php maintenance
```

اجرای موفق در صفحه «سیستم» و داشبورد دیده می‌شود. اگر Cron اجرا نشود، داشبورد هشدار می‌دهد.

## ۶. پس از نصب

1. ورود به آدرس پنل مدیریت ← «حساب من» ← فعال‌سازی **ورود دومرحله‌ای TOTP** (Google Authenticator / Aegis / 2FAS).
2. «کاربران» ← «کاربر جدید»: رمز موقت یک بار نمایش داده می‌شود؛ آن را از کانال امن به کاربر بدهید. کاربر در اولین ورود رمز را تغییر می‌دهد.
3. آدرس مخفی کاربران را فقط حضوری یا از کانال امن بدهید؛ هرگز در وب، شبکه اجتماعی یا ایمیل عمومی منتشر نکنید.
4. روش ورود پیش‌فرض «نام کاربری و رمز عبور» است. برای OTP: «تنظیمات» ← ارائه‌دهنده پیامک ← کلید API ← «ارسال آزمایشی» ← سپس تغییر روش ورود.
5. گزینه «فقط تست — ذخیره کد در فایل لاگ» را هرگز در استفاده واقعی فعال نگذارید.

## ۷. پشتیبان‌گیری

- **دیتابیس:** cPanel ← Backup ← Download a MySQL Database Backup (یا JetBackup). شامل هش رمزها و داده‌های غیرمحتوایی است.
- **فایل `config/.env`:** حاوی کلید برنامه و رمز دیتابیس است؛ نسخه پشتیبان آن را جدا و رمزنگاری‌شده نگه دارید.
  بدون `APP_KEY`، کلید API پیامک و راز TOTP مدیران قابل بازیابی نیست (باید دوباره تنظیم شوند).
- از فاز ۴، پوشه `storage/attachments` (فایل‌های رمزنگاری‌شده با عمر ۷ روز) طبق سند ۰۸ از بکاپ مستثنا یا با نگهداری ≤ ۷ روز.

## ۸. به‌روزرسانی (نسخه‌های بعدی)

فایل‌های پوشه‌های `app/`، `database/` و `public/` را با نسخه جدید جایگزین کنید (به `config/` و `storage/` دست نزنید).
اجرای migrationهای جدید در نسخه‌های بعد از طریق پنل انجام خواهد شد.

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| `/install` هم 404 می‌دهد | `.htaccess` به `public_html` کپی نشده، یا `mod_rewrite`/AllowOverride فعال نیست |
| «پوشه storage قابل نوشتن نیست» | مجوز پوشه‌ها: `storage` و `config` باید 755 و مالک حساب باشند |
| خطای اتصال دیتابیس | نام کامل با پیشوند حساب (`user_db`) و میزبان `localhost` |
| ریدایرکت بی‌پایان به https | پروکسی/CDN با SSL انعطاف‌پذیر؛ SSL را روی Full قرار دهید |
| همه کاربران با هم محدودیت نرخ می‌خورند | پشت CDN (مثلاً Cloudflare) IP واقعی دیده نمی‌شود؛ پشتیبانی از IP مورد اعتماد پروکسی در فاز بعد |
