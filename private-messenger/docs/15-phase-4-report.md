# ۱۵ — گزارش فاز ۴: پیام‌رسانی کامل و رسانه رمزنگاری‌شده

## ۱. امکانات پیام (همه داخل رمزنگاری سرتاسری)

همه موارد زیر «رویداد» رمزنگاری‌شده‌اند؛ سرور حتی نمی‌تواند تشخیص دهد یک envelope متن است، واکنش است یا ویرایش.

| امکان | توضیح |
|---|---|
| پاسخ | نقل پیام اصلی؛ کلیک روی نقل‌قول به پیام می‌رود |
| ویرایش | فقط پیام متنی خود؛ گیرنده فقط از نویسنده اصلی می‌پذیرد؛ برچسب «ویرایش‌شده» |
| حذف برای همه / برای من | حذف برای همه فقط از نویسنده پذیرفته می‌شود |
| واکنش | ۶ ایموجی؛ کلیک دوباره واکنش را برمی‌دارد |
| سنجاق | نوار «سنجاق‌شده» بالای گفتگو |
| بازارسال | متن یا فایل؛ فایل دوباره آپلود نمی‌شود — سرور فقط دسترسی گفتگوی جدید را ثبت می‌کند (به شرط دسترسی فرستنده) |
| رسید خوانده‌شدن | ✓ ارسال، ✓✓ تحویل، ✓✓ آبی خوانده‌شده |
| نشانگر تایپ | رمزنگاری‌شده؛ فقط برای دستگاه‌هایی که در ۲۰ ثانیه اخیر آنلاین بوده‌اند (جلوگیری از گسست ratchet؛ vodozemac بیش از ۲۰۰۰ پیام گمشده را نمی‌پذیرد) |
| جست‌وجو | فقط روی همین دستگاه؛ هیچ عبارتی به سرور ارسال نمی‌شود |
| پیام‌های خوانده‌نشده | شمارنده در فهرست گفتگوها |

رویدادی که زودتر از پیام هدفش برسد (مثلاً واکنش) نگه داشته می‌شود و پس از رسیدن پیام اعمال می‌شود.

## ۲. فایل، تصویر، ویدیو، صدا

| مورد | پیاده‌سازی |
|---|---|
| رمزنگاری | AES-256-GCM روی دستگاه فرستنده با ساختار STREAM: قطعه‌های ۲۵۶KB، nonce شامل شماره قطعه و پرچم «آخرین قطعه» — جابه‌جایی، کوتاه‌سازی یا افزودن تشخیص داده می‌شود |
| فراداده | نام، نوع، اندازه، ابعاد، مدت و thumbnail فقط داخل پیام رمزنگاری‌شده؛ سرور فقط حجم ciphertext را می‌بیند |
| آپلود | چندبخشی (هر بخش مضرب قطعه رمزنگاری، ~۸۰٪ `post_max_size`، حداکثر ۸MB)، SHA-256 هر بخش، تکرار خودکار با تأخیر افزایشی و پرسیدن وضعیت از سرور پس از قطع اتصال |
| ذخیره | خارج از docroot، نام تصادفی ۲۵۶ بیتی، بدون پسوند، هرگز اجرا نمی‌شود |
| دانلود | فقط اعضای گفتگویی که فایل به آن فرستاده شده؛ پشتیبانی Range؛ رمزگشایی جریانی روی دستگاه |
| تصویر HD | تغییر اندازه روی دستگاه به ضلع بلند ۲۵۶۰px، JPEG ۹۰٪، حذف EXIF/مکان |
| تصویر اصلی | بایت‌به‌بایت همان فایل (در تست تأیید شد)؛ هشدار احتمال وجود اطلاعات مکان |
| ویدیو | ارسال با کیفیت اصلی + thumbnail و مدت روی دستگاه فرستنده. **انتخاب کیفیت کمتر (360p…1080p) پیاده نشده** و طبق سند نمایش داده نمی‌شود |
| پیام صوتی | ضبط با میکروفون دستگاه (Opus/WebM یا MP4 در Safari)، رمزنگاری و پخش پس از رمزگشایی |
| فهرست رسانه‌ها | دکمه «رسانه‌ها» در هر گفتگو |

## ۳. سیاست نگهداری ۷ روزه و فضا

- انقضا ۷ روز پس از تکمیل آپلود؛ **فایل منقضی بلافاصله از دسترس خارج می‌شود** (410)، حتی پیش از حذف فیزیکی.
- حذف فیزیکی خودکار (Cron یا خودکار هنگام استفاده) یا دستی از پنل؛ آپلودهای ناتمام پس از ۴۸ ساعت.
- حساب‌های «نگهداری دائمی» حذف نمی‌شوند؛ لغو آن مهلت ۷ روزه از زمان لغو می‌دهد؛ فایل منقضی‌شده با فعال‌سازی برنمی‌گردد.
- **بدون سقف نرم‌افزاری حجم** (پیش‌فرض)؛ سقف اختیاری در تنظیمات. در کمبود فضای دیسک آپلود با پیام روشن متوقف می‌شود و هیچ فایلی بی‌اجازه حذف نمی‌شود.
- کنترل سوءاستفاده (نه سقف حجم): آپلودهای ناتمام هر کاربر حداکثر ۲۵٪ فضای آزاد.
- صفحه «فضا و فایل‌ها» در پنل: تعداد و حجم فایل‌ها، دائمی، منقضی در انتظار حذف، ناتمام، فضای آزاد، سهمیه (ورودی مدیر — PHP سهمیه cPanel را نمی‌تواند بخواند)، آخرین پاک‌سازی.
- سرور برای حذف هیچ فایلی را رمزگشایی نمی‌کند (و نمی‌تواند).

## ۴. تست‌ها (`tests/run-all.sh` — ۲۱۹ مورد، همه موفق)

| مجموعه | تعداد |
|---|---|
| واحد + سرویس (شامل ۵ تست جدید فایل) | ۳۶ |
| پروتکل WASM | ۱۲ |
| انتها‌به‌انتها HTTP | ۹۸ |
| پذیرش E2EE مرورگر (فاز ۳) | ۲۷ |
| **پذیرش فاز ۴ در مرورگر (سه کاربر)** | ۲۹ |
| نصب‌کننده تک‌فایلی | ۱۷ |

نمونه موارد فاز ۴: رسید خوانده‌شدن، تایپ، پاسخ، واکنش، ویرایش، حذف برای همه، محدودیت ویرایش/حذف به نویسنده، سنجاق، جست‌وجوی محلی؛
تصویر HD (۲۵۶۰px) و اصلی (بایت‌به‌بایت یکسان)؛ **فایل ۱۵ مگابایتی با قطع عمدی اتصال وسط آپلود ← ادامه و دریافت بایت‌به‌بایت یکسان**؛
ذخیره فقط ciphertext خارج از وب؛ پیام صوتی با میکروفون (مجازی)؛ ویدیو؛ بازارسال فایل به نفر سوم بدون آپلود دوباره؛
عدم دسترسی نفر سوم به فایل‌هایی که برایش فرستاده نشده (404)؛ فایل منقضی ← 410 فوری؛ پاک‌سازی دستی ← حذف فایل از دیسک؛
**dump دیتابیس: هیچ متن پیام، نام فایل یا محتوای فایل یافت نشد.**

## ۵. محدودیت‌ها (صادقانه)

1. **ادامه آپلود پس از بستن یا بارگذاری دوباره صفحه** پشتیبانی نمی‌شود (مرورگر دسترسی به فایل را از دست می‌دهد)؛ ادامه پس از قطع اتصال در همان صفحه کار می‌کند. پیام «ارسال نشد» با دکمه تلاش دوباره نمایش داده می‌شود.
2. فایل دریافتی برای نمایش در حافظه مرورگر رمزگشایی می‌شود؛ فایل‌های بسیار بزرگ (چند گیگابایت) روی گوشی ممکن است به محدودیت حافظه بخورند.
3. تبدیل کیفیت ویدیو (360p تا 1080p) پیاده نشده است؛ ویدیو با کیفیت اصلی ارسال می‌شود.
4. پیش‌نمایش گالری چندتصویری به‌صورت پیام‌های جدا نمایش داده می‌شود.
5. همچنان: یک دستگاه برای هر حساب و نبود کلید بازیابی (فاز ۶)، فقط Chromium تست خودکار شد، اعلان Push نیست.
