# ۱۴ — گزارش فاز ۳: پایه رمزنگاری سرتاسری (E2EE)

## ۱. نتیجه Spike (دروازه ورود به فاز ۳ — سند ۰۴)

| معیار | نتیجه |
|---|---|
| ساخت vodozemac 0.11.2 به WebAssembly | ✔ موفق، با feature رسمی `wasm_js` |
| اندازه | ۴۰۶KB (فشرده ۱۴۶KB) — هدف < ۱.۵MB |
| نسخه پروتکل | **Olm v1** (نسخه پایدار و ممیزی‌شده). Olm v2 در این نسخه vodozemac «آزمایشی» است و استفاده نشد |
| اجرا در مرورگر | ✔ Chromium (تست خودکار کامل). **Firefox و Safari در این محیط قابل تست نبودند** |
| سازگاری امضای Ed25519 با PHP sodium | ✔ تست شد |
| مقاومت پساکوانتومی | ✘ Olm v1 پساکوانتومی نیست؛ ادعایی در این باره نمی‌شود |

پل Rust (`crypto-wasm/src/lib.rs`) هیچ رمزنگاری‌ای پیاده نمی‌کند و فقط انواع داده را برای JavaScript تبدیل می‌کند.
خروجی ساخته‌شده (`app/resources/assets/pm_crypto*.{js,wasm}`) در مخزن قرار دارد تا روی سرور نیازی به build نباشد.

## ۲. آنچه ساخته شد

| بخش | توضیح |
|---|---|
| موتور رمزنگاری در مرورگر (`e2ee-worker.js`) | Web Worker جدا از صفحه؛ همه کلیدها و متن‌های آشکار فقط اینجا |
| ساخت کلید روی دستگاه | حساب Olm (Curve25519 + Ed25519)، کلید امضای اصلی کاربر (MSK)، ۵۰ کلید یک‌بارمصرف + کلید fallback، همه امضاشده |
| ذخیره محلی | IndexedDB؛ کلیدها و پیام‌ها با کلید AES-GCM **غیرقابل‌استخراج** Web Crypto رمز می‌شوند |
| گواهی دستگاه | هر دستگاه با MSK کاربر امضا می‌شود؛ گیرنده فقط برای دستگاه‌های دارای گواهی معتبر رمز می‌کند (جلوگیری از «دستگاه شبح») |
| تبادل کلید | 3DH با کلید یک‌بارمصرف (امضای آن بررسی می‌شود) و سپس Double Ratchet |
| ارسال/دریافت | یک envelope رمزنگاری‌شده برای هر دستگاه؛ سرور پوشش دقیق همه دستگاه‌ها را الزامی می‌کند؛ envelope پس از تحویل حذف می‌شود |
| اتصال پیام به گفتگو و فرستنده | شناسه گفتگو، فرستنده، دستگاه و پیام داخل متن رمزنگاری‌شده است؛ سرور نمی‌تواند پیام را جابه‌جا یا جعل کند |
| شماره امنیتی | ۶۰ رقم به روش منتشرشده Signal (SHA-512 تکراری ۵۲۰۰ بار) + علامت «تأییدشده» |
| هشدار تغییر کلید | کلید اصلی هر مخاطب در اولین تماس ثبت می‌شود؛ در صورت تغییر، ارسال تا پذیرش صریح کاربر متوقف می‌شود |
| اتصال دوباره پس از خروج/ورود | نشست جدید فقط با امضای چالش یک‌بارمصرف با کلید دستگاه به دستگاه وصل می‌شود |
| یک تب در هر زمان | Web Locks؛ دو تب همزمان وضعیت ratchet را خراب می‌کردند |
| وضعیت پیام | ⏳ در صف، ✓ ارسال‌شده، ✓✓ تحویل‌شده، ⚠ ارسال‌نشده (با تلاش دوباره) |
| پنل مدیریت | فهرست دستگاه‌های رمزنگاری هر کاربر (فقط اثر انگشت کلید عمومی)، لغو دستگاه، بازنشانی هویت |
| نصب ساده | فایل تکی `install.php` + ساخت خودکار دیتابیس و Cron از طریق API خود cPanel (سند ۱۲) |

## ۳. تست‌ها (همه اجرا شد و موفق بود — `tests/run-all.sh`)

| مجموعه | تعداد |
|---|---|
| واحد + سرویس (PHP، MariaDB) | ۳۱ |
| پروتکل روی WASM واقعی (Node) | ۱۲ |
| انتها‌به‌انتها HTTP (Apache + HTTPS + `.htaccess`) | ۹۸ |
| **پذیرش E2EE در مرورگر واقعی (دو کاربر)** | ۲۷ |
| نصب‌کننده تک‌فایلی (با شبیه‌ساز API cPanel) | ۱۷ |

مهم‌ترین موارد آزمون پذیرش مرورگر:
- آلیس پیام می‌فرستد، باب روی دستگاه خودش رمزگشایی می‌کند، پاسخ می‌دهد؛ ✓✓ تحویل نمایش داده می‌شود.
- **dump کامل دیتابیس (متنی و hex)، همه فایل‌های storage و config، و لاگ‌های وب‌سرور جست‌وجو شدند: متن پیام‌ها هیچ‌جا وجود ندارد.**
- سرور فقط کلیدهای عمومی ۳۲ بایتی دارد؛ ستونی برای کلید خصوصی وجود ندارد.
- دستکاری ciphertext در دیتابیس ← گیرنده پیام را رد می‌کند و ادامه گفتگو سالم است.
- شماره امنیتی دو طرف یکسان است.
- پس از بازنشانی کلید باب، آلیس هشدار می‌گیرد و تا پذیرش، ارسال قفل است؛ دستگاه قدیمی باب اعلام «نامعتبر» می‌کند.
- تاریخچه پس از بارگذاری دوباره از ذخیره رمزنگاری‌شده محلی خوانده می‌شود؛ تب دوم رد می‌شود.

## ۴. محدودیت‌های فعلی (صادقانه)

1. **فقط یک دستگاه برای هر حساب.** ورود از مرورگر/گوشی دوم یعنی «ساخت کلید جدید» (دستگاه قبلی از کار می‌افتد و مخاطبان هشدار می‌گیرند). اتصال چند دستگاه با QR در **فاز ۶**.
2. **کلید بازیابی هنوز وجود ندارد (فاز ۶).** پاک کردن داده‌های مرورگر = از دست رفتن تاریخچه آن دستگاه. این موضوع در خود برنامه به کاربر گفته می‌شود. روی iPhone فقط حالت نصب‌شده (Add to Home Screen) توصیه می‌شود.
3. **فقط Chromium تست خودکار شد.** Firefox و Safari باید روی دستگاه واقعی آزمایش شوند.
4. فعلاً فقط پیام متنی. پاسخ، ویرایش، حذف، واکنش، رسید «خوانده‌شده»، جست‌وجو و فایل در **فاز ۴**.
5. تحویل با polling هر ۲.۵ ثانیه (در پس‌زمینه ۱۵ ثانیه)؛ اعلان Push هنوز نیست.
6. محافظت از یکپارچگی کد (manifest امضاشده، تهدید T-01) هنوز پیاده نشده است.
7. **ممیزی امنیتی مستقل** پیش از استفاده حساس همچنان توصیه می‌شود.
