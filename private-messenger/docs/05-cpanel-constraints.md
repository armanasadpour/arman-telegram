# ۰۵ — محدودیت‌های واقعی cPanel و راهکارها

> هیچ‌کدام از این موارد فرض گرفته نمی‌شود؛ همه با اسکریپت [`tools/host-probe/probe.php`](../tools/host-probe/)
> روی هاست واقعی اندازه‌گیری و در نصب‌کننده هم دوباره بررسی می‌شوند. **تا زمانی که خروجی probe از
> هاست هدف دریافت نشود، بخش «وضعیت هاست هدف» این سند خالی است.**

## ۱. جدول محدودیت‌ها

| # | محدودیت رایج | اثر | راهکار در طراحی | نحوه تشخیص |
|---|---|---|---|---|
| 1 | **عدم وجود پروسه دائمی / WebSocket** | پیام‌رسانی بلادرنگ واقعی ممکن نیست | polling تطبیقی (پیش‌فرض)، long-poll مشروط، WebSocket فقط اگر هاست اجازه دهد | probe: `proc_open`/`exec`، وجود Application Manager (Passenger) |
| 2 | **Entry Processes (EP) در CloudLinux/LVE** (معمولاً ۱۰–۳۰) | long-poll هر کاربر یک EP اشغال می‌کند ← خطای 508 | long-poll خاموش به‌صورت پیش‌فرض؛ فعال‌سازی فقط اگر (کاربران آنلاین × ۱) < ۵۰٪ EP | خواندن `/proc/self/...` ممکن نیست؛ از مدیر خواسته می‌شود مقدار EP را از cPanel (Resource Usage) وارد کند |
| 3 | `max_execution_time` (۳۰–۶۰ ثانیه) و `set_time_limit` غیرفعال | درخواست‌های طولانی قطع می‌شوند | همه درخواست‌ها کوتاه؛ دانلود با Range قطعه‌ای | `ini_get`، تست `set_time_limit` |
| 4 | `upload_max_filesize`/`post_max_size` (۲–۱۲۸MB) | سقف هر درخواست | **chunk size پویا** = `min(post_max, upload_max) × 0.8`، با سقف ۸MB | `ini_get` + تست واقعی ارسال بدنه با اندازه‌های افزایشی |
| 4b | **رفتار PHP بالاتر از `post_max_size`** | در تست محلی PHP 8.3، بدنه خام `octet-stream` بزرگ‌تر از `post_max_size` همچنان از `php://input` تحویل شد اما هشدار startup ثبت شد (با `display_errors=On` می‌تواند پاسخ را خراب کند) | برنامه به این رفتار تکیه **نمی‌کند**؛ chunk همیشه زیر `post_max_size` | probe مقدار دریافتی و `post_max_size` را کنار هم گزارش می‌کند |
| 5 | **ModSecurity** | ممکن است بدنه باینری یا JSON بزرگ base64 را مسدود کند | chunkها `application/octet-stream` خام؛ envelopeها JSON با سقف معقول؛ تست در نصب | ارسال آزمایشی بدنه باینری و JSON نمونه |
| 6 | `LimitRequestBody` Apache / LiteSpeed | سقف پنهان بدنه | همان تست واقعی بند ۴ | تست |
| 7 | **سهمیه دیسک کاربر** | `disk_free_space()` فضای کل پارتیشن را برمی‌گرداند، **نه سهمیه حساب** | سهمیه از cPanel UAPI (`Quota::get_quota_info`) با API Token اختیاری، یا ورود دستی مقدار سهمیه توسط مدیر؛ محاسبه مصرف از DB + اندازه واقعی storage | probe هر دو مقدار را نمایش و تفاوت را هشدار می‌دهد |
| 8 | **سهمیه inode** (مثلاً ۱۰۰–۲۵۰ هزار فایل) | هر فایل/قطعه یک inode | هر آپلود در **یک فایل** با نوشتن در offset ذخیره می‌شود (نه یک فایل برای هر chunk)؛ پاک‌سازی آپلودهای ناتمام | از مدیر پرسیده/از UAPI خوانده می‌شود |
| 9 | Cron با حداقل فاصله ۱ تا ۱۵ دقیقه یا غیرفعال | پاک‌سازی و ارسال push زمان‌بندی‌شده | انقضا در **زمان کوئری** اعمال می‌شود (مستقل از Cron)؛ Cron فقط حذف فیزیکی؛ در نبود Cron: هشدار پنل + دکمه اجرای دستی + «pseudo-cron» اختیاری در درخواست‌های عادی (حداکثر یک بار در ۱۰ دقیقه، با قفل DB) | آخرین اجرای Cron در جدول `cron_runs` |
| 10 | `exec`/`shell_exec`/`proc_open` غیرفعال | FFmpeg و ابزار اسکن قابل اجرا نیست | **برای E2EE اصلاً لازم نیست** (سرور ciphertext دارد) | probe |
| 11 | نبود TURN | تماس پشت NAT متقارن/CGNAT برقرار نمی‌شود | STUN + TURN خارجی اختیاری؛ پیام شفاف خطا | تست ICE در فاز ۵ |
| 12 | docroot ثابت `public_html` برای دامنه اصلی | قرار دادن کد خارج از وب | کد در `~/private-messenger/`، فقط `public/` در docroot؛ ترجیحاً ساب‌دامین با docroot = `~/private-messenger/public` | probe: مسیر docroot و قابلیت نوشتن یک سطح بالاتر |
| 13 | نسخه MySQL/MariaDB قدیمی | `SKIP LOCKED`، JSON | حداقل MySQL 8.0 یا MariaDB 10.6؛ در غیر این صورت نصب متوقف می‌شود | `SELECT VERSION()` |
| 14 | `allow_url_fopen`/cURL خروجی محدود | ارسال پیامک و Web Push | cURL الزامی؛ تست اتصال خروجی به ارائه‌دهنده پیامک | probe |
| 15 | OPcache با `validate_timestamps=0` | به‌روزرسانی کد دیده نمی‌شود | `opcache_reset()` در فرایند به‌روزرسانی | probe |
| 16 | LiteSpeed به‌جای Apache | تفاوت جزئی `.htaccess` | فقط دستورهای سازگار مشترک | `$_SERVER['SERVER_SOFTWARE']` |
| 17 | MIME نوع `.wasm` | WASM با MIME نادرست streaming-compile نمی‌شود | `AddType application/wasm .wasm` در `.htaccess` + fallback بارگذاری ArrayBuffer | تست HTTP |
| 18 | حافظه مرورگر گیرنده برای فایل‌های بسیار بزرگ | رمزگشایی کل فایل در RAM | رمزگشایی جریانی به File System Access API (Chromium) یا Service Worker stream download؛ روی iOS سقف عملی محدود است و نمایش داده می‌شود | feature detection در کلاینت |
| 19 | Safari: حذف ذخیره‌سازی سایت پس از ۷ روز عدم استفاده (سایت نصب‌نشده) | از دست رفتن کلیدها | الزام نصب PWA روی iOS + کلید بازیابی اجباری | تشخیص `display-mode: standalone` |

## ۲. طراحی polling و برآورد بار

فرض: ۵۰ کاربر همزمان، ۲۰ نفر با گفتگوی باز.

- گفتگوی باز: ۲۰ کاربر × ۱ درخواست / ۲.۵ ثانیه = ۸ req/s
- باز بدون گفتگوی فعال: ۳۰ × ۱/۱۰ = ۳ req/s
- مجموع ≈ ۱۱ req/s، هر کدام چند میلی‌ثانیه CPU و یک کوئری ایندکس‌دار ← برای هاست اشتراکی متوسط قابل تحمل.
- همزمانی EP: با زمان پاسخ ~۵۰ms، میانگین EP اشغال‌شده < ۱. (در long-poll همین ۵۰ کاربر ~۵۰ EP اشغال می‌کنند ← دلیل خاموش بودن پیش‌فرض.)
- بهینه‌سازی: پاسخ `204` سریع با بررسی یک ستون `devices.last_event_id` پیش از کوئری کامل؛ `ETag`/`cursor`.

**اعلام شفاف به کاربر/مدیر:** تأخیر تحویل پیام در حالت polling معمولاً ۱–۳ ثانیه و در پس‌زمینه وابسته به Web Push است.

## ۳. حالت‌های قرارگیری فایل‌ها

| حالت | ساختار | امنیت | وضعیت |
|---|---|---|---|
| **A (ترجیحی)** | ساب‌دامین (مثلاً `chat.example.com`) با docroot = `~/private-messenger/public` | کد و storage کاملاً خارج از وب | پیشنهاد اصلی |
| **B** | `~/private-messenger/` + کپی `public/*` در `~/public_html/`؛ `index.php` مسیر app را از فایل پیکربندی می‌خواند | خوب | پذیرفته |
| **C** | هاست اجازه نوشتن خارج از `public_html` نمی‌دهد | ضعیف: کد و storage داخل docroot با `.htaccess Deny` | **نصب متوقف می‌شود** مگر probe HTTP ثابت کند فایل نگهبان (canary) در storage از وب قابل دریافت نیست؛ حتی در این صورت هشدار دائمی در پنل |

نصب‌کننده در هر حالت یک فایل canary تصادفی در `storage/` و `config/` می‌نویسد و تلاش می‌کند آن را از
طریق HTTP دریافت کند؛ اگر موفق شود، نصب متوقف می‌شود.

## ۴. ابزار probe (فاز ۱)

`tools/host-probe/probe.php` را با یک توکن تصادفی در نام یا پارامتر روی هاست هدف آپلود کنید، خروجی JSON/HTML
را ذخیره و **بلافاصله فایل را حذف کنید**. راهنما: [`tools/host-probe/README.md`](../tools/host-probe/README.md).

## ۵. وضعیت هاست هدف

_در انتظار خروجی probe از هاست واقعی._ پس از دریافت، این بخش با مقادیر واقعی و تصمیم‌های مربوط
(chunk size، حالت sync، حالت قرارگیری، وضعیت Cron) تکمیل می‌شود.
