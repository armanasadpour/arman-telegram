# فاز ۵ — همکاران فروش، کیف پول و قیمت همکاری

**ورودی:** فاز ۴ (بسته‌ها، موتور قیمت، Snapshot) و فاز ۳ (ساخت اکانت امن در سرور).

## طراحی مالی (اصول غیرقابل مذاکره)
1. هر همکار یک **کیف پول** دارد؛ مبالغ به **ریال** و عدد صحیح.
2. **دفتر کل (Ledger) تغییرناپذیر:** هر تغییر موجودی یک ردیف جدید است (هیچ ردیفی ویرایش یا حذف نمی‌شود). اصلاح خطا = ردیف معکوس با ارجاع به ردیف اصلی.
3. **موجودی = جمع ردیف‌ها**؛ موجودی ذخیره‌شده فقط کش است و دستور/دکمه «تطبیق» آن را با جمع ردیف‌ها مقایسه می‌کند.
4. **موجودی منفی ممنوع:** برداشت با قفل سطری (`SELECT … FOR UPDATE`) داخل تراکنش انجام می‌شود؛ اگر کافی نباشد هیچ چیز ثبت نمی‌شود.
5. **Idempotent:** هر ردیف کلید یکتا دارد؛ تکرار همان درخواست ردیف دوم نمی‌سازد.
6. شارژ دستی مدیر: **دلیل اجباری + تأیید مجدد رمز + Audit** (زمان، مدیر، شناسه تراکنش).
7. شارژ آنلاین کیف پول فقط پس از **تأیید قطعی پرداخت** (درگاه‌ها در فاز ۷؛ سرویس کیف پول از هم‌اکنون نقطه ورود آن را دارد).
8. شارژ کیف پول **درآمد فروش نیست**؛ نوع هر ردیف (شارژ، خرید، بازگشت وجه، اصلاح) جدا ثبت می‌شود تا گزارش‌های فاز ۹ آن‌ها را تفکیک کنند.

## قیمت همکار (قواعد صریح)
ترتیب انتخاب — **فقط یکی** اعمال می‌شود:
1. **قیمت ثابت اختصاصی** همان بسته برای همان همکار
2. **تخفیف دسته‌ای** همکار (درصد، برای دسته بسته)
3. **تخفیف سراسری** همکار (درصد، روی همه بسته‌ها)
4. در غیر این صورت **قیمت عمومی** (با تخفیف عمومی فاز ۴)

درصدها روی **قیمت پایه** بسته محاسبه می‌شوند (تخفیف عمومی روی آن جمع نمی‌شود). **حفاظت:** قیمت همکار هرگز از قیمت عمومی همان لحظه بیشتر نیست؛ اگر تخفیف عمومی بیشتر بود، قیمت عمومی ملاک است (انتخاب کمترین، نه جمع کردن).

## فروش همکار
1. قیمت خرید همکار محاسبه و **Snapshot** می‌شود؛ همکار **قیمت فروش به مشتری** را وارد می‌کند؛ **سود = قیمت فروش − قیمت خرید** ثبت می‌شود.
2. ابتدا برداشت از کیف پول (اگر کافی نباشد فروش انجام نمی‌شود)، سپس ساخت/تمدید در سرور.
3. شکست **قطعی** (سرور درخواست را رد کرد یا ساخت لغو و پاک‌سازی شد) ← **بازگشت خودکار وجه** با ردیف جداگانه.
4. وضعیت **نامشخص** (قطع ارتباط وسط کار) ← «نیازمند رسیدگی»؛ پول برنمی‌گردد تا وضعیت سرور روشن شود؛ Cron آن را پیگیری و تکمیل یا بازپرداخت می‌کند.

## دسترسی
- همکار با همان صفحه ورود وارد **پنل همکار** (`/r`) می‌شود و فقط داده‌ها، اکانت‌ها و فروش‌های **خودش** را می‌بیند؛ به هیچ صفحه مدیریتی دسترسی ندارد.
- ساختار زیرمجموعه (همکارِ همکار) با ستون `parent_id` پیش‌بینی شده ولی **غیرفعال** است تا تصمیم جداگانه.

## معیارهای پذیرش
- [ ] موجودی منفی غیرممکن؛ درخواست تکراری دو بار کسر نکند؛ تطبیق موجودی با جمع دفتر کل.
- [ ] شارژ/کسر دستی با دلیل، مدیر، زمان و شناسه تراکنش؛ ردیف‌ها تغییرناپذیر.
- [ ] قیمت همکار طبق ترتیب بالا؛ بدون جمع شدن تخفیف‌ها.
- [ ] فروش موفق: کسر + اکانت + سود؛ شکست قطعی: بازگشت خودکار؛ نامشخص: رسیدگی بدون از دست رفتن پول.
- [ ] همکار فقط داده خودش را ببیند (تست دسترسی متقاطع).
- [ ] تست‌های فازهای قبل سبز.
