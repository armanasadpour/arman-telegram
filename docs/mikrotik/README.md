# توسعه میکروتیک (L2TP و WireGuard)

## مرحله ۱ — اتصال به روتر (نسخه 1.1.0) ✅
- **چند روتری:** جدول `routers`؛ رمز رمزنگاری‌شده؛ هر روتر L2TP و/یا WireGuard را جدا فعال می‌کند.
- **سه روش اتصال:**
  - REST API روی HTTPS (پیشنهادی؛ RouterOS 7.1+، سرویس www-ssl).
  - API-SSL (پورت 8729).
  - API ساده (پورت 8728؛ رمز رمزنگاری نمی‌شود — فقط شبکه خصوصی).
- **اعتماد به گواهی (Pinning):** گواهی خودامضای روتر بدون ارسال رمز دریافت و SHA-256 آن نمایش داده می‌شود تا با `/certificate print detail` مقایسه و تأیید شود. پس از آن پنل فقط به همان کلید رمز می‌فرستد؛ تغییر آدرس/روش اتصال اعتماد را باطل می‌کند.
- **تست اتصال:** نام، نسخه، برد، لایسنس، CPU، حافظه، uptime.
- **بررسی آمادگی (فقط خواندنی):** محدودیت IP سرویس مدیریتی، سرویس‌های ناامن، سرور L2TP، IPsec، پروفایل PPP با Pool، کاربران PPP موجود، اینترفیس WireGuard و آدرس آن، Peerهای موجود. کلیدهای خصوصی و PSK هرگز ذخیره یا نمایش داده نمی‌شوند.
- **اسکریپت راه‌اندازی:** گروه و کاربر مخصوص پنل محدود به IP هاست، گواهی خودامضا، فعال‌سازی سرویس فقط برای IP هاست.
- **پایش:** `routers:health` هر ۵ دقیقه؛ هشدار قطع/وصل در ربات.
- **تست‌ها:** ۱۰ تست (شبیه‌ساز واقعی RouterOS API و HTTPS با گواهی: ورود، رمز اشتباه، عدم تطابق گواهی، بررسی آمادگی، پایش)؛ کل ۲۱۳ تست روی SQLite و MariaDB سبز. تست مرورگری روی Apache: افزودن روتر ← دریافت و تأیید گواهی ← تست ← فعال‌سازی پروتکل‌ها.

## مراحل بعد (پیشنهادی)
2. **مدل اکانت چندپروتکلی و بسته‌ها:** نوع سرویس هر بسته/گروه (OpenVPN-IBSng / L2TP / WireGuard)، حجم و روز دلخواه، دسته‌بندی و قیمت‌گذاری مشترک با موتور فعلی.
3. **L2TP:** ساخت `/ppp secret` با پروفایل و محدودیت سرعت؛ حسابداری با خواندن دوره‌ای شمارنده‌های اتصال فعال؛ قطع و غیرفعال‌سازی خودکار با پایان حجم/زمان؛ محدودیت اتصال همزمان.
4. **WireGuard:** تولید کلید روی سرور، تخصیص IP یکتا، ساخت Peer، فایل `.conf` و QR؛ حسابداری با شمارنده rx/tx هر Peer (تشخیص ری‌استارت)؛ غیرفعال‌سازی خودکار.
5. **ربات و همکاران و پرداخت** برای پروتکل‌های جدید (همان جریان‌های فعلی).
