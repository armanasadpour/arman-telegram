# گزارش فاز ۱ — بررسی IBSng و معماری

**وضعیت:** تحویل‌شده، در انتظار (۱) اجرای ابزار اثبات روی سرور واقعی و (۲) تأیید شما.

## ۰. دامنه نسخه اول (تصمیم کارفرما — 2026-11-24)

- **نسخه اول فقط OpenVPN از طریق IBSng** را پوشش می‌دهد (IBSng فقط برای OpenVPN استفاده می‌شود).
- **L2TP و WireGuard (اتصال مستقیم MikroTik) به فاز توسعه بعدی موکول شد.** معماری با «Adapter پروتکل» طراحی می‌شود تا افزودن MikroTik بعداً بدون تغییر هسته ممکن باشد. ابزار و کلاینت REST میکروتیک و طرح [05-multi-protocol.md](05-multi-protocol.md) برای آن زمان حفظ می‌شوند.
- تحویل OpenVPN به مشتری: نام کاربری/رمز + فایل `.ovpn` از پروفایل تعریف‌شده در پنل.

## ۲. کارهای انجام‌شده

1. دریافت سورس رسمی `IBSng-A1.24.tar.bz2` و بررسی مستقیم کد (نه مستندات ثانویه).
2. استخراج کامل فهرست متدهای XML-RPC، آرگومان‌ها، کلید ویژگی‌های کاربر، رفتار خطا و احراز هویت.
3. ساخت **ابزار اثبات اتصال** [`tools/ibsng-probe`](../../tools/ibsng-probe/README.md): PHP خالص، بدون Composer، نصب با File Manager، فارسی و واکنش‌گرا، محافظت با توکن، گزارش JSON بدون رمز. کلاینت XML-RPC آن هسته `IbsConnector` فاز ۳ خواهد بود.
4. طراحی معماری، API داخلی، طرح اتصال امن، ERD و انتخاب فناوری.

## ۴. یافته‌های کلیدی که روی طراحی اثر دارند

1. **رمز مدیر IBSng بدون رمزنگاری در هر درخواست ارسال می‌شود** → اتصال باید از شبکه خصوصی یا Relay امن عبور کند.
2. **IBSng «سقف حجم کل» ندارد.** فروش حجمی با مدل **credit + تعرفه حجمی (cpk)** انجام می‌شود؛ نیازمند تعریف Charge حجمی در IBSng و ارسال Accounting توسط NAS است.
3. **ساخت اکانت دو مرحله‌ای و غیراتمیک است** → Saga با کلید Idempotency و Reconciliation طراحی شد.
4. **Webhook ندارد** → همگام‌سازی مصرف/آنلاین با Cron و Polling دسته‌ای.
5. `ext-xmlrpc` در PHP 8 وجود ندارد → کلاینت اختصاصی (ساخته و تست شد).

## ۶. اقدام لازم از سمت شما برای بستن فاز ۱

1. ✔️ اعلام شد: دو سرور جدا در یک محل داخل ایران، OpenVPN روی میکروتیک، PHP 8+، فونت IRANSans. باقی‌مانده: شبکه خصوصی بین دو سرور هست؟ نسخه RouterOS؟ Interim-Update فعال است؟
2. ابزار `tools/ibsng-probe` را طبق [راهنما](../../tools/ibsng-probe/README.md) روی هاست اجرا کنید (ابتدا فقط خواندنی، سپس تست نوشتن).
3. گزارش JSON را ارسال کنید. **رمز یا توکن را در گفتگو نفرستید**؛ گزارش آن‌ها را ندارد.
4. تصمیم‌های بخش ۵ را تأیید یا اصلاح کنید.
