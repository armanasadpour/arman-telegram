# گزارش فاز ۱ — بررسی IBSng و معماری

**وضعیت:** تحویل‌شده، در انتظار (۱) اجرای ابزار اثبات روی سرور واقعی و (۲) تأیید شما.

| وظیفه | معیار پذیرش | وضعیت |
|---|---|---|

وابستگی‌ها: دسترسی شبکه از هاست cPanel به IBSng، یک حساب مدیر IBSng، یک گروه آزمایشی.

## ۲. کارهای انجام‌شده

1. دریافت سورس رسمی `IBSng-A1.24.tar.bz2` و بررسی مستقیم کد (نه مستندات ثانویه).
2. استخراج کامل فهرست متدهای XML-RPC، آرگومان‌ها، کلید ویژگی‌های کاربر، رفتار خطا و احراز هویت.
3. ساخت **ابزار اثبات اتصال** [`tools/ibsng-probe`](../../tools/ibsng-probe/README.md): PHP خالص، بدون Composer، نصب با File Manager، فارسی و واکنش‌گرا، محافظت با توکن، گزارش JSON بدون رمز. کلاینت XML-RPC آن هسته `IbsConnector` فاز ۳ خواهد بود.
4. طراحی معماری، API داخلی، طرح اتصال امن، ERD و انتخاب فناوری.

## ۳. نتایج تست

| تست | نتیجه |
|---|---|
| ۲۵ تست واحد کدک XML-RPC (رمزگذاری/رمزگشایی، UTF-8 فارسی، Fault، XXE، اعداد) | ✅ همه موفق |
| ۹ تست انتها‌به‌انتها با شبیه‌ساز IBSng (خواندن، نوشتن+پاکسازی، رمز اشتباه، پورت بسته، قفل تست نوشتن، عدم نشت رمز) | ✅ همه موفق |
| صفحه وب: بدون توکن ← 403؛ نمایش موبایل ۳۹۰px بدون اسکرول افقی | ✅ |
| **اجرا روی IBSng واقعی** | ⏳ منتظر اجرای شما |

> شبیه‌ساز فقط سازگاری قالب سیم و منطق ابزار را ثابت می‌کند؛ **اثبات واقعی فقط با گزارش JSON از سرور شما کامل می‌شود.**

## ۴. یافته‌های کلیدی که روی طراحی اثر دارند

1. **رمز مدیر IBSng بدون رمزنگاری در هر درخواست ارسال می‌شود** → اتصال باید از شبکه خصوصی یا Relay امن عبور کند.
2. **IBSng «سقف حجم کل» ندارد.** فروش حجمی با مدل **credit + تعرفه حجمی (cpk)** انجام می‌شود؛ نیازمند تعریف Charge حجمی در IBSng و ارسال Accounting توسط NAS است.
3. **ساخت اکانت دو مرحله‌ای و غیراتمیک است** → Saga با کلید Idempotency و Reconciliation طراحی شد.
4. **Webhook ندارد** → همگام‌سازی مصرف/آنلاین با Cron و Polling دسته‌ای.
5. `ext-xmlrpc` در PHP 8 وجود ندارد → کلاینت اختصاصی (ساخته و تست شد).

## ۵. تصمیم‌هایی که تأیید شما را لازم دارند

| # | موضوع | پیشنهاد |
|---|---|---|
| ۱ | مسیر اتصال به IBSng | ✔️ با توجه به هم‌محل بودن: **اتصال محلی** (`127.0.0.1` اگر یک ماشین است، وگرنه IP داخلی). Relay لازم نیست ([جزئیات](04-environment-mikrotik.md)) |
| ۲ | مدل حجم | **credit + Charge حجمی** (۱ credit = ۱ مگابایت)؛ برای بسته‌های ماهانه با ریست: `traffic_periodic_accounting_monthly` |
| ۳ | شروع انقضا | پیش‌فرض: **از اولین اتصال** (`rel_exp_date`)؛ قابل تغییر به «از زمان خرید» (`abs_exp_date`) |
| ۴ | فریم‌ورک | **Laravel با vendor داخل ZIP**، هدف PHP 8.3 (حداقل 8.2) |
| ۵ | تلگرام در هاست ایران | ✔️ Relay لازم است؛ پیشنهاد: ارسال از Relay و دریافت با Polling از Cron ([جزئیات](04-environment-mikrotik.md#۲-تلگرام-هاست-داخل-ایران)) |
| ۷ | قطع اتصال کاربر در میکروتیک | IBSng این کار را با SSH انجام می‌دهد؛ اگر با RouterOS شما ناسازگار بود، راه جایگزین پیش از اجرا به تأیید شما می‌رسد |
| ۶ | فونت IRANSans | ✔️ تأیید شد — کارفرما لایسنس دارد. فایل‌های فونت (woff2/woff) در فاز ۲ از کارفرما دریافت و داخل بسته نصب قرار می‌گیرند؛ در مخزن عمومی Commit نمی‌شوند |

## ۶. اقدام لازم از سمت شما برای بستن فاز ۱

1. ✔️ اعلام شد: هاست و IBSng هم‌محل و داخل ایران، NAS میکروتیک، PHP 8+. باقی‌مانده: یک ماشین هستند یا دو ماشین؟ نسخه RouterOS و نوع سرویس VPN؟ Interim-Update فعال است؟
2. ابزار `tools/ibsng-probe` را طبق [راهنما](../../tools/ibsng-probe/README.md) روی هاست اجرا کنید (ابتدا فقط خواندنی، سپس تست نوشتن).
3. گزارش JSON را ارسال کنید. **رمز یا توکن را در گفتگو نفرستید**؛ گزارش آن‌ها را ندارد.
4. تصمیم‌های بخش ۵ را تأیید یا اصلاح کنید.
